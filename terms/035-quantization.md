# 035 Quantization（量化）

## ① 英文术语

Quantization

## ② 中文翻译

量化

## ③ 一句话定义

量化，就是把模型里那些用高精度、占地方大的数字（通常是 16 位或 32 位浮点数）表示的权重和激活值，压缩成低精度、占地方小的数字（比如 8 位、4 位整数），从而大幅缩小模型体积、加快运算速度、降低显存占用，代价是损失一点点精度。

## ④ 核心知识

### 1. 为什么需要量化：模型的"体重问题"

我们以前讲过参数（第 15 讲），一个 70 亿参数（7B）的模型，如果每个参数都用 32 位浮点数（FP32）存，那光权重就要占 70 亿 × 4 字节 = 28GB。这只是参数本身，还没算推理时中间结果（激活值）、KV 缓存等开销。所以一个 7B 模型，FP32 全精度下通常需要 28GB 以上显存才跑得动，普通消费级显卡（8GB、16GB、24GB）根本装不下。

量化的本质思路很简单：**我们真的需要 32 位这么高的精度吗？** 大量实验证明，神经网络的权重对"小误差"相当不敏感。把 3.14159 存成 3.14，模型输出几乎不变。于是人们把数字从高精度"降级"到低精度，用精度换空间和速度。这就是量化。

### 2. 核心原理：从浮点到整数

先说清楚"精度"是什么意思。计算机里存小数有几种常见格式：

- **FP32（32 位浮点数）**：1 位符号 + 8 位指数 + 23 位尾数，范围巨大、精度高，是深度学习训练的默认格式。
- **FP16（16 位浮点数）**：1 + 5 + 10，体积减半。
- **BF16（16 位脑浮点）**：1 + 8 + 7，指数位数和 FP32 一样多，所以范围大、但精度略低，训练时更稳定，是现在主流训练格式。
- **INT8（8 位整数）**：只能表示 -128 到 127 这 256 个值。
- **INT4（4 位整数）**：只能表示 -8 到 7 这 16 个值。

量化的做法，就是把原来分布在一段连续范围内的浮点数，**映射**到一小撮离散的整数格点上。映射方式叫"线性量化"，公式大致是：

```
q = round(x / scale) + zero_point
```

其中 `scale`（缩放因子）和 `zero_point`（零点偏移）是两个额外算出来的小量。反向恢复时：

```
x ≈ (q - zero_point) × scale
```

你只需要存一大堆整数 `q`，外加每组一个 `scale` 和 `zero_point`。整数占的字节少，这就是省空间、省带宽的根本原因。

### 3. 两种量化粒度：逐层 vs 逐张量 vs 逐组 vs 逐通道

量化不是全模型用同一个 scale，因为不同层的数值范围天差地别。粒度越细，精度损失越小，但额外开销越大：

- **逐张量（per-tensor）**：整层共用一个 scale，最省，但误差最大。
- **逐通道（per-channel）**：卷积/线性层的每个输出通道各一个 scale，精度明显更好，是权重量化的常用选择。
- **逐组（group-wise）**：把权重切成一小组一小组，每组一个 scale，是 4-bit 及以下量化的主流做法（GGUF 里常见 32/64/128 一组）。
- **逐 token / 逐元素**：最细，但开销大，一般只对激活值用动态方式处理。

一句话：**越细越准，越粗越省**，工程上要在这两者之间权衡。

### 4. 关键区分：训练后量化（PTQ） vs 量化感知训练（QAT）

量化在什么时候做，是两种完全不同的路线：

- **PTQ（Post-Training Quantization，训练后量化）**：模型已经训练好了，直接对它的权重做量化，不需要重新训练。优点是零成本、几分钟就能搞定，缺点是精度可能掉得比较多，尤其到 4-bit 甚至更低时。现在最主流的做法（比如 llama.cpp 的 GGUF、GPTQ、AWQ）都属于这一类。为了减小误差，PTQ 通常会拿一小撮"校准数据"过一遍模型，统计每层激活值的分布，来更聪明地设定 scale（这步叫校准 calibration）。
- **QAT（Quantization-Aware Training，量化感知训练）**：在训练过程中就"假装"模型是低精度的，让前向计算用量化后的值、反向传播用高精度更新权重，这样模型主动学会了如何在低精度下仍然表现好。QAT 精度损失最小，但成本高、要重新训练，所以普通开发者很少自己跑 QAT，更多是模型厂商在发布时做。

对绝大多数用开源模型的人，接触到的是 PTQ 的产物。

### 5. 历史脉络与重要方法

量化的思想其实很老，神经网络压缩从 1990 年代就有研究，但真正在 LLM 时代爆发，是因为模型大到"不量化就跑不动"。

- **2016 年前后**：Google 提出 8-bit 推理的思路，Binarized Neural Networks（二值网络，XNOR-Net，2016）把权重压到 1 位，震惊学界，证明极端低精度也勉强能用。
- **2018 年**：TensorRT 等推理框架把 INT8 量化工业化。
- **GPTQ（2022，Frantar 等人）**：基于经典的 Optimal Brain Surgeon（OBS）剪枝思想，用二阶导数信息逐列修正权重，把模型量化到 3-bit/4-bit，效果大幅提升，是 4-bit 量化的里程碑之一。
- **AWQ（2023，MIT 韩松团队）**：发现不是所有权重都同样重要，大约 1% 的"显著权重"贡献了大部分输出质量，于是对这部分权重做特殊保护（不量化或单独缩放），把 4-bit 量化的精度损失进一步压低。
- **GGUF / llama.cpp（2023 起，Georgi Gerganov）**：这是把量化"平民化"的关键一步。llama.cpp 是一个纯 C++ 的推理引擎，能在 CPU 上跑 LLM，配合 GGUF 格式的量化模型（q4_0、q4_K_M、q5_K_M、q8_0 等一大堆档位），让普通人用一台 MacBook 甚至手机就能跑 7B、13B 模型。今天你从 Hugging Face 下的很多 `.gguf` 文件，就是各种量化档位。
- **QLoRA（2023，Dettmers 等人）**：把 4-bit 量化（用 NF4，一种专门给权重分布设计的数据格式）+ LoRA 微调（第 33 讲）结合起来，让普通人在一张 24GB 显卡上就能微调 65B 的模型。这是"量化 + 微调"结合的经典案例。

### 6. 前沿进展：4-bit 以下、混合精度与"量化友好"训练

- **4-bit 成为事实标准**：目前开源社区默认的"性价比甜点"是 4-bit（尤其 AWQ 和 GGUF 的 K 系列）。再往上（8-bit）几乎无损但省得不多；再往下（3-bit、2-bit）体积更小但质量明显下滑，一般只用于特殊场景。
- **混合精度（mixed precision）**：不是所有层都量化到同一档位。敏感层（比如 embedding、输出层、注意力里的某些矩阵）用高精度，其余用低精度，既省又稳。很多 GGUF 档位本身就是混合设计。
- **FP8 训练**：NVIDIA 的 H100 之后原生支持 FP8，训练阶段也能用 8 位浮点加速，这是量化从"推理优化"延伸到"训练优化"的趋势。
- **量化友好的训练**：既然量化是绕不开的，与其事后硬压，不如训练时就设计成"抗量化"的（比如用更平滑的权重分布），让 4-bit 甚至 3-bit 下精度掉得更少。这是一个活跃的研究方向。
- **推理硬件协同**：量化能不能真提速，取决于硬件是否支持对应的低精度矩阵运算（比如 INT8/INT4 的 Tensor Core）。软件量化省了显存，但速度提升还要看芯片。

### 7. 一句话总结原理

量化 = 用"小整数 + 缩放因子"去近似"大浮点数"，用可接受的一点精度损失，换体积、显存、带宽、速度的全方位收益。它和蒸馏（第 34 讲）目标类似——都是"变轻变快"，但蒸馏是换一个更小的模型，量化是给同一个模型"瘦身压缩"，两者还能叠加使用。

## ⑤ 实际场景

- 你在本地跑一个开源模型，显存不够，看到文件后缀 `.gguf` 或标注 `q4_K_M`、`AWQ`、`GPTQ`，就是在选量化档位——数字越小越省显存但越笨。
- 用 Ollama、LM Studio、llama.cpp 这类工具时，"量化等级"下拉菜单选的就是这个。
- 想在一台手机或树莓派上跑 7B 模型，必须上 4-bit 甚至 3-bit 量化才装得下。
- 看模型厂商宣称"我们的模型只需 X GB 显存"，背后往往就是量化在帮忙。
- 你自己做微调，显存不够时用 QLoRA，本质就是量化 + LoRA 的组合拳。

## ⑥ 关联术语

- **LoRA（低秩适配，第 33 讲）**：QLoRA = 量化 + LoRA，两者常一起出现。
- **Distillation（知识蒸馏，第 34 讲）**：同样为了"变小变快"，但路线不同，可叠加。
- **Inference（推理，第 9 讲）**：量化主要优化的是推理阶段的显存和速度。
