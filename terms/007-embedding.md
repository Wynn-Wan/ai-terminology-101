# Embedding（嵌入 / 向量化）

- ② 中文翻译：嵌入 / 向量化
- ③ 一句话定义：把文字、图片、音频等「非结构化」的东西，转换成一组固定长度的数字（向量），让机器能通过「算距离」来理解它们的语义相似度。

---

## ④ 核心知识

### 先建立直觉：为什么需要「把词变成数字」

计算机本质上只会做数字运算。一段文字「我喜欢猫」在它眼里就是一串字符编码，它根本不知道「猫」和「狗」比「猫」和「汽车」更接近。而 Embedding 要解决的，就是把这种「语义」翻译成数学：让「猫」和「狗」在某个高维空间里靠得近，「猫」和「汽车」离得远。

所以 Embedding 不是随便编一个数字，而是一种**有语义结构的位置编码**：每个词、每句话、每张图，都被「摁」进一个高维空间里的一个点。这个空间里，**方向相近 = 语义相近**。

### 最经典的案例：king - man + woman = queen

2013 年，Google 的 Tomas Mikolov 团队发表了 Word2Vec（论文《Efficient Estimation of Word Representations in Vector Space》），这是 Embedding 真正进入大众视野的标志。他们发现了一件让所有人震惊的事：

```
vec("king") - vec("man") + vec("woman") ≈ vec("queen")
```

「国王」减去「男人」加上「女人」，结果向量最接近「王后」。这说明这个向量空间不只存了「相似度」，还编码了**语义关系**（比如性别、时态、首都关系等）。这不是人告诉它的规则，而是模型在大量文本里自己「统计」出来的。

### 原理：一个「用上下文猜词」的游戏

Word2Vec 的核心思想非常朴素，甚至有点反直觉——它不靠任何语言学标注，只靠一个任务：**预测一个词的邻居**。

- **CBOW（连续词袋）**：给你上下文，猜中间缺的词。比如「我___猫」，猜是「喜欢」。
- **Skip-gram**：给你一个词，猜它周围会出现什么词。比如给「猫」，猜上下文里有「宠物」「可爱」「老鼠」。

模型为了把这个「猜词游戏」玩好，被迫把每个词映射成一个向量，而且**语义相近的词（它们周围出现的词也相近）自然就会被拉近**。这就是著名的「分布假说」（Distributional Hypothesis）——「一个词的意义，由它周围的词决定」，这句话最早可以追溯到语言学家 Firth（1957 年）："You shall know a word by the company it keeps."

这里的关键洞察是：**Embedding 是「副产品」，不是目标**。模型在完成某个预测任务时，中间层学到的权重，恰好就是我们要的向量表示。

### 从「词的嵌入」到「句子的嵌入」

Word2Vec 解决的是单个词。但现实里我们面对的是整句话、整段文章。于是出现了几种思路：

1. **取平均**：把句子里每个词的向量加起来求平均（简单但粗糙，会丢失词序信息）。
2. **Transformer 时代的句子嵌入**：让模型把整句话读进去，输出一个「代表整句话」的向量。代表作品是 2018 年的 BERT（Google），以及专门为「检索/相似度」优化的 **Sentence-BERT**（2019，Nils Reimers 等）。它用孪生网络（Siamese Network）结构，让两个句子的向量直接算余弦相似度，速度比原版 BERT 快很多。
3. **基于对比学习的现代方案**：OpenAI 的 text-embedding 系列、Cohere 的 embed、以及开源的 BGE（BAAI 智源）、E5、GTE 等，都是当前做 RAG（检索增强生成）的主力。

### 一个绕不开的操作：余弦相似度

有了向量，怎么算「两个东西有多像」？最常用的方法是**余弦相似度（Cosine Similarity）**：

```
相似度 = (A · B) / (|A| × |B|)
```

它衡量的是两个向量的**夹角**，而不是长度。值在 -1 到 1 之间，越接近 1 越像。为什么要用夹角而不是欧氏距离？因为在高维空间里，向量的长度往往和「词频、句子长度」有关，用夹角能把这些干扰因素消掉，更纯粹地反映「语义方向」。

另一个配套操作是**归一化（normalization）**：把所有向量长度统一成 1，这样点积就等于余弦相似度，计算更快。

### 关键概念清单

- **向量维度（dimension）**：向量的长度，常见有 384、768、1024、1536、3072 等。维度越高，能表达的信息越丰富，但存储和计算成本也越高。
- **稠密向量（dense vector）**：Embedding 都是稠密的——几乎每个数字都有值，这和早期的 one-hot、TF-IDF 这种「稀疏」表示形成对比。
- **嵌入空间（embedding space）**：所有向量共同生活的那个高维空间，语义结构就体现在点的相对位置里。
- **多模态嵌入**：把文字和图片映射到**同一个空间**，这样「一张猫的照片」的向量和「cat」这个词的向量能直接比较。代表是 OpenAI 的 CLIP（2021）。

### 历史脉络（一张简表）

| 时间 | 方法 | 关键点 |
| --- | --- | --- |
| 2013 | Word2Vec | 词嵌入，发现 king - man + woman ≈ queen |
| 2014 | GloVe（Stanford） | 用全局词共现矩阵，另一种经典词嵌入 |
| 2018 | ELMo / BERT | 上下文相关嵌入（同一个词在不同句子里的向量不同） |
| 2019 | Sentence-BERT | 让句子嵌入可以高效算相似度 |
| 2021 | CLIP | 图文跨模态嵌入 |
| 2022+ | text-embedding / BGE / E5 等 | 面向 RAG 检索的现代嵌入模型 |

### 前沿进展与当前主流

现在做 Embedding，大家最关心两件事：**检索质量（是不是能找对东西）** 和 **成本**。

- **对比学习成为标配**：训练时给「正样本对」（意思相近的）和「负样本对」（不相关的），逼模型把正样本拉近、负样本推远。负样本的质量直接决定模型上限。
- **长文本嵌入**：早期模型只能处理 512 token，现在很多模型支持 8192 甚至更长，能直接对整篇文档生成向量。
- **多语言嵌入**：让不同语言但同义的句子落在同一位置，中英文可以直接互相检索。
- **Matryoshka（俄罗斯套娃）嵌入**：一个向量可以无损地「截断」成更短版本，用低维度也能保持大部分性能，大大节省存储。
- **ColBERT 等「多向量」方案**：不再是一句话一个向量，而是每个 token 一个向量，在「精确度」和「延迟」之间做折中，属于检索增强里的精细流派。

> 一句话总结核心知识：Embedding 的本质是「用预测任务当借口，逼模型学会语义空间里的坐标」。它从 Word2Vec 的词级表示，一路演化到 Transformer 时代的句子级、跨模态表示，是今天所有 RAG、语义搜索、推荐系统、聚类分析的地基。

## ⑤ 实际场景（万 sir 会在哪儿碰到它）

- **RAG 检索增强**（上一讲刚学过）：你的文档库要「切块 → 转成向量 → 存进向量库 → 用户提问时找最相关的几块」。这里的「转成向量」就是 Embedding。
- **语义搜索**：搜「怎么让抠图的边缘更自然」，系统能找到「修边」「去白边」的文章，哪怕一个词都对不上——因为它比的是语义向量，不是字面关键词。
- **推荐系统**：把商品和用户都变成向量，谁离得近就推荐谁。
- **聚类 / 去重**：把一堆图片或评论全转成向量，自动把相似的分成一堆。
- **跨模态检索**：用文字搜图片、用图片搜文字（CLIP 干的就是这个）。
