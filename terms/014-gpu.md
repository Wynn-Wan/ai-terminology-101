# 014 · GPU（Graphics Processing Unit）

- ① 英文术语：GPU（Graphics Processing Unit）
- ② 中文翻译：图形处理器
- ③ 一句话定义：GPU 是一种为了「同时做大量简单计算」而生的芯片，本来是拿来渲染游戏画面的，结果阴差阳错成了训练和运行 AI 模型的主力引擎。
- ④ 核心知识
- ⑤ 实际场景
- ⑥ 关联术语

---

## 一句话定义

GPU 是一种为「大规模并行计算」设计的处理器：它的本职工作是同时计算屏幕上几百万个像素点的颜色，但这种「一次干很多件小事」的能力，恰好就是训练大模型最需要的东西。

---

## 核心知识

### 1. 先搞清楚：CPU 和 GPU 到底差在哪

我们平时说的「处理器」，默认指的是 **CPU（中央处理器）**。CPU 的设计哲学是「少数几个超级能干的工人」——它擅长做复杂的、有逻辑依赖的事情，比如「如果 A 成立就做 B，否则做 C」，而且每一步都要求算得又快又准。

GPU 反着来：它是「几千个能力一般但数量极多的工人」。单个 GPU 核心比 CPU 核心笨得多，但架不住它多——一块现代 GPU 上有成千上万个核心，可以同时开工。

打个比方：

- **CPU** 像一位外科医生，一台手术做得极其精细，但一次只能做一台。
- **GPU** 像一万个流水线装配工，每个人只会拧一颗螺丝，但一秒钟能同时拧一万颗。

训练大模型这件事，本质上是「几十亿次一模一样的乘加运算」，没有复杂的 if-else 分支，全是重复劳动。这种活，正好撞在 GPU 的枪口上。

### 2. 从游戏显卡到 AI 算力的历史拐点

GPU 最早是给游戏服务的。上世纪 90 年代，3D 游戏兴起，画面要从一堆三角形网格算出每个像素的颜色，这个计算量巨大但极其「可并行」。于是英伟达（NVIDIA）、ATI（后被 AMD 收购）等公司开始做专门处理图形的芯片，这就是 GPU 这个名字的由来——Graphics Processing Unit。

关键的转折发生在 2006 年前后：

- 英伟达推出了 **CUDA**（Compute Unified Device Architecture，统一计算设备架构）。这是一个让程序员可以直接用 GPU 做「通用计算」的编程平台——不再只是画图，你可以让 GPU 帮你算任何大规模并行的问题。
- 这一年成了分水岭：GPU 从「只能画画的显卡」变成了「通用并行计算引擎」。学界叫它 **GPGPU**（General-Purpose computing on GPU，通用目的 GPU 计算）。

### 3. 深度学习为什么「认准」了 GPU

神经网络有两个天然适合 GPU 的特点：

1. **矩阵乘法密集**。神经网络的每一层，本质上就是把输入向量乘上一个巨大的权重矩阵。矩阵乘法是「可并行」的典型代表——里面每一个数的乘法都可以同时做。
2. **数据量大但运算简单**。训练一个模型要喂进去海量数据，每个样本做的是几乎相同的计算步骤。

2009 年，斯坦福的 **吴恩达（Andrew Ng）** 团队发表了一篇有里程碑意义的论文，用 GPU 训练深度学习模型，速度比 CPU 快了近 70 倍，成本却降了快十倍。这篇论文让整个学界意识到：**深度学习 + GPU 是绝配**。

再到 2012 年，**AlexNet** 在 ImageNet 图像识别大赛上一骑绝尘，用的就是两块英伟达 GPU。这一年通常被认为是「深度学习革命」的引爆点。从此，GPU 成了 AI 圈的硬通货。

### 4. GPU 到底是怎么「并行」的（大白话版）

GPU 内部的核心组织方式是分层的，理解这套结构才能看懂后面那些术语：

- 最底层是 **CUDA Core**（在英伟达架构里这么叫）：就是那个「只会拧螺丝的工人」。
- 一堆 CUDA Core 组成一个 **SM**（Streaming Multiprocessor，流式多处理器），可以理解成一个「班组」，班组内可以共享一小块极快的内存。
- 很多 SM 再组成整块 GPU。

程序跑起来时，成千上万个线程被组织成「波」「块」，同一时刻执行**同一条指令**，但作用于**不同的数据**——这叫 **SIMT**（Single Instruction, Multiple Threads，单指令多线程）。

另一个关键概念是 **显存（VRAM，Video RAM）**：GPU 板卡上自带的高速内存。模型参数、中间激活值都要放在显存里。所以你会经常听到「这模型显存不够跑不了」「80G 显存」这类说法——显存大小直接决定你能塞下多大的模型。

### 5. 为什么训练 AI 这么「吃 GPU」

训练一个 LLM 需要的算力，普通人很难有直观概念。几个数字感受一下：

- 训练 GPT 级别的大模型，需要的算力单位是 **FLOPs**（浮点运算次数），往往以「万亿亿次（10^18，即 ExaFLOP）」来计。
- 现在衡量 GPU 算力的常见单位是 **FLOPS**（每秒浮点运算次数），高端数据中心 GPU 可以达到每秒几百 TFLOPS 甚至 PFLOPS 级别。

训练大模型不只是「算得快」就行，还涉及一个卡脖子的东西：**显存带宽**。训练时数据要不停地在显存里搬运，搬得慢，算得再快也没用。这也是为什么高端 AI 芯片都用 **HBM（高带宽内存）**——把内存堆叠起来，换取超高的数据传输速度。

顺带说一个词：**Tensor Core（张量核心）**。这是英伟达后来加进 GPU 的专用硬件单元，专门加速矩阵乘加运算（就是神经网络里最核心的那种运算），比普通 CUDA Core 做同样的活快很多。现在说「AI 算力」，很大程度上指的就是这些 Tensor Core 的性能。

### 6. 前沿进展：从「通用 GPU」到「专用 AI 芯片」

这几年的趋势是：**AI 算力不再只有通用 GPU 一条路**。

- **英伟达**：把 GPU 做成了「AI 全家桶」，从芯片（Hopper、Blackwell 架构）到互联（NVLink、NVSwitch）到软件生态（CUDA），一整套护城河。这也是它市值冲到全球前列的原因。
- **AMD**：走「开放生态」路线，推 ROCm 平台，抢英伟达的份额。
- **Google 的 TPU**：张量处理单元，从 2016 年就自研的专用 AI 芯片，不卖给别人，专供自家云和数据中心。
- **各种「AI 加速卡」**：亚马逊的 Trainium/Inferentia、微软的 Maia、以及大量国内厂商（华为昇腾、寒武纪、燧原等），都在做「只为 AI 服务」的专用芯片。

趋势的本质是：**训练和推理对芯片的要求其实不一样**。训练要「算得快、显存大、互联强」；推理（模型上线后回答用户）要「便宜、省电、够快就行」。所以未来会越来越分化——训练用顶级 GPU 集群，推理用更省成本的专用芯片。

### 7. 一句话总结这条知识链

> 深度学习靠矩阵乘法 → 矩阵乘法天生可并行 → GPU 天生擅长并行 → 于是 GPU 成了 AI 时代的「发动机」。

理解了这个因果链，你就理解了为什么「买 GPU」「抢算力」会成为 AI 行业最核心的话题。

## 实际场景

- **你自己跑模型**：本地跑 Stable Diffusion 画图、跑本地大模型，电脑有没有一块好的 NVIDIA 显卡（以及显存够不够大），体验天差地别。
- **云上训练/推理**：在云平台（AWS、阿里云、AutoDL 等）租 GPU 实例，按小时计费，贵的能到几十块一小时——这就是「算力成本」。
- **看新闻**：英伟达股价、芯片出口管制、「算力即国力」、大厂囤 GPU——这些新闻背后全是同一个词。
- **选硬件时**：你会看到「A100、H100、4090、3090」这些型号，其实都是英伟达 GPU 的不同型号，价格和算力天差地别。

## 关联术语

- **CUDA**：英伟达的 GPU 编程平台，是「让 GPU 干通用计算」的关键软件。理解 GPU 绕不开它。
- **Inference（推理）**：GPU 既用于「训练」也用于「推理」，两者对算力的要求不同，是我们第 9 讲已经聊过的概念。
- **Tensor Core（张量核心）**：GPU 里专门加速 AI 运算的硬件单元，后面深入聊算力时还会再遇到。
