# 009 · Inference（推理）

- ① 英文术语：**Inference**
- ② 中文翻译：**推理**（在工程语境里也常直接说「推断」或「推理阶段」）
- ③ 一句话定义：模型训练完成后，拿训练好的权重对**新的输入**跑一遍前向计算、产出结果的这个过程，就叫推理（Inference）。

---

## ④ 核心知识

先说一个大前提，帮你把「训练」和「推理」这两个词彻底分开，后面一切都建立在这个区分上。

一个神经网络，本质上是一大堆参数（权重、偏置）。它在被「训练」之前，这些参数是随机数，啥也不会干。所谓**训练（Training）**，就是拿海量数据反复「喂」它，让它根据预测结果和标准答案之间的差距，反向去调整这些参数——这个过程里既要算**前向传播**（从输入一路算到输出），也要算**反向传播**（把误差从输出一路传回输入，用来更新每个参数）。训练是「调参数」的阶段，重、慢、贵。

而**推理（Inference）**，是训练完、参数已经「冻住」之后发生的事：你给它一个它从没见过的输入，它只跑一遍**前向传播**，用现有参数直接算出结果，**不再更新任何参数**。所以业界有句很形象的话：**「训练时学习，推理时使用。」** 训练是「做题+对答案+改错」，推理是「直接考试」。

### 1. 为什么推理被单独拎出来当成一个词

因为在深度学习里，训练和推理是两个**资源消耗和优化目标完全不同**的阶段：

- **训练**追求的是「把参数调好」，要能承受巨大的算力和时间成本，通常跑在成百上千张 GPU 上，一跑就是几天到几个月。
- **推理**追求的是「又快又省又便宜」地把结果吐出来，因为它要**面向真实用户、实时响应、跑在成百上千次甚至上亿次的规模**上。

一个模型训练可能花几百万美元，但把它部署上线后，每一次用户提问都是一次推理。如果单次推理贵 1 分钱，每天一亿次调用就是每天多烧 100 万——所以「推理成本」和「推理速度」是整个行业最关心的工程问题之一。这就是为什么「Inference」这个词，在 LLM 时代几乎天天被挂在嘴边。

### 2. 历史脉络：从「前向传播」到「推理服务」

这个词的根，可以追到统计和逻辑学里——「从已知前提推出结论」叫 inference。机器学习借用了它：一个训练好的模型，就是一个「从输入到输出」的规则，拿它去算新样本，就是「从已学到的知识推出答案」，所以叫 inference。

在深度学习兴起之前，传统机器学习（决策树、SVM 等）也有推理，但那时模型小、算得快，没人专门为「推理」这个环节大动干戈。真正让「推理」变成一门独立工程学问的，是深度神经网络变大之后：

- 2012 年 AlexNet 在 ImageNet 夺冠，深度卷积网络爆发，人们开始意识到「训练完的模型要部署到服务器/手机上跑」是个真问题，于是出现了**模型压缩、量化、剪枝**这些专门服务推理的技术。
- 2017 年《Attention Is All You Need》提出 **Transformer**（后面第 18 讲会展开），自回归生成成为主流，推理的形态从「一次前向出结果」变成「一个 token 一个 token 地生成」，推理的性能问题被彻底放大。
- 2022 年底 ChatGPT 爆火后，大语言模型的推理成为独立的、巨大的商业赛道，催生了「推理引擎」「推理优化」「推理芯片」一整套产业。

### 3. 关键概念：推理的两个核心特征

**（1）自回归生成（Autoregressive Generation）**

现代 LLM 生成文本，不是一次性算出整段话，而是**一个 token 一个 token 地「吐」**：先算出第一个词的概率分布，选一个，把它拼到输入后面，再算下一个词……直到输出结束符或到达长度上限。

这带来的直接后果是：**生成一段 500 个 token 的回复，模型内部要做 500 次前向计算**，而且这 500 次是**串行**的（下一步依赖上一步的结果）。所以「生成长文本」比「读长文本」慢得多，这正是你感觉 ChatGPT 像在「打字」而不是「秒回整段」的根本原因。

**（2）Decoding 采样（Temperature、Top-p 等）**

推理阶段「选下一个词」不是死板地永远选概率最高的那个，而是有一套**解码策略**：Temperature（温度）、Top-p、Top-k 等。这些参数**只在推理阶段生效**，训练时用不到。它们决定了输出是「保守刻板」还是「灵活发散」——这是第 23 讲「Temperature」的内容，这里先埋个伏笔。

### 4. 重要论文与人物

- **2017 ·《Attention Is All You Need》**（Vaswani 等人，Google）：Transformer 架构，是今天几乎所有大模型推理的底座。
- **2016 ·《Deep Compression》**（韩松 Song Han）：系统性地提出剪枝、量化和霍夫曼编码，是「推理优化」这个方向的奠基作之一。
- **2017 ·《Efficient Processing of Deep Neural Networks: A Tutorial and Survey》**（Vivienne Sze 等人，MIT）：把「面向推理的硬件与算法协同设计」讲成体系，是推理加速领域的经典综述。
- 从产业角度看，**OpenAI、NVIDIA、AMD**，以及后起的 **Groq、Cerebras** 等推理芯片公司，加上开源的推理框架 **vLLM、TensorRT-LLM、llama.cpp**，是推动「推理工程化」的主要力量。

### 5. 前沿进展：推理优化正在成为主战场

训练一个模型是一次性投入，但推理是**持续烧钱**的环节，所以优化空间也最大。几个当前很热的方向：

- **量化（Quantization）**：把模型参数从 16 位浮点数压成 8 位、甚至 4 位整数，推理时算得飞快、省内存，精度损失可控。你听说的「INT8」「GPTQ」「AWQ」都是量化技术。
- **KV Cache（键值缓存）**：自回归生成时，之前算过的 token 的中间结果可以缓存复用，避免重复计算——这是几乎所有 LLM 推理引擎的标配优化。
- **投机采样（Speculative Decoding）**：用一个小模型「先猜」几个 token，再用大模型一次性验证，猜对了就白赚几步，能显著提速。
- **批处理与并发（Continuous Batching）**：把多个请求动态打包一起算，提升 GPU 利用率，vLLM 就是靠这个出名的。
- **专用推理芯片**：NVIDIA 之外，Groq 的 LPU、Cerebras 的晶圆级芯片，都在赌「推理」这个更大、更持久的市场。

### 6. 一个必须厘清的歧义：推理 ≠ 会思考

中文里「推理」很容易让人联想到「逻辑思考、动脑分析」。但在 AI 术语里，**Inference 这个词和「思考能力」没有半毛钱关系**，它只是一个中性、技术性的词，意思是「把输入过一遍模型、得到输出」这个计算动作本身，哪怕模型输出的是一句胡话，那也是「推理」。

所以当你看到「推理芯片」「推理成本」「推理延迟」这些词时，脑子里要自动翻译成「**跑模型、出结果**」，而不是「模型在思考」。至于「让模型像人一样一步步思考」，那是第 25 讲 **Chain of Thought（思维链）** 要讲的东西，和这里的 Inference 是两个层面的事。

## ⑤ 实际场景

你几乎天天在跟「推理」打交道，只是没意识到：

1. **你每次用 ChatGPT / Claude / 各种 AI 助手发消息**，后端就是在对你这句话做一次（其实是很多次 token 级别的）推理。你看到它逐字输出，就是自回归推理的直观表现。
2. **手机上的语音助手、输入法联想、相册自动分类、人脸识别解锁**：这些都是训练好的小模型被「塞」进手机里做本地推理，不联网、低延迟、省电。
3. **刷短视频时的推荐系统**：模型根据你的行为实时推理出「你下一个更想看什么」。
4. **自动驾驶的感知模块**：摄像头拍到的每一帧画面，都要经过模型推理，识别出车、人、车道线，这个推理还必须快到毫秒级，否则车就撞了。
5. **API 计费**：现在调用大模型 API，基本都按「输入 token + 输出 token」收费，输出 token 就是推理时生成的部分。你关心的「这个功能一个月要花多少 API 钱」，本质就是在估算「推理成本」。

## ⑥ 关联术语

- **Training（训练）**：推理的另一半，二者是一对。记住「训练调参数、推理用参数」就分清了。
- **Latency（延迟）**：推理最核心的性能指标之一，指「从发出请求到拿到结果」的耗时，下一组术语就会碰到。
- **Temperature（温度）**：只在推理阶段起作用的采样参数，决定输出有多「放飞」。
- **Chain of Thought（思维链）**：让人以为「推理=思考」的罪魁祸首（笑），其实它是「让模型输出思考过程」的提示技巧，和这里的 Inference 是两码事。
