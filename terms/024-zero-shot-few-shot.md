# 024 Zero-shot / Few-shot

- ② 中文翻译：零样本 / 少样本
- ① 英文术语：Zero-shot / Few-shot（全称 Zero-shot Learning / Few-shot Learning，以及少样本里最常用的 Few-shot Prompting）

## 一句话定义

Zero-shot / Few-shot 说的是「让模型干一件它没专门训练过的任务时，给它多少示例」：不给任何示例直接让它干，叫零样本（Zero-shot）；给它一两个到几十个示例「照着学」，叫少样本（Few-shot）。

---

## 核心知识

### 1. 先厘清一个关键区分：这词有「两种身份」

「Zero-shot / Few-shot」在 AI 圈里其实指的是两件不同的事，初学者最容易在这里绕晕，务必先拆开：

- **身份一：机器学习里的「学习范式」（Learning Paradigm）**。传统机器学习要训练一个模型，得给大量标注好的数据。Zero-shot Learning 指「训练时没见过这个类别，测试时却能认出来」；Few-shot Learning 指「每个类别只给极少量样本（比如 1 个、5 个）就能学会」。这是学术界几十年的老话题，研究的是**模型怎么用极少数据泛化**。

- **身份二：LLM 时代的「提示技巧」（Prompting Technique）**。大模型预训练时已经「看过全世界」，很多任务它其实早就会了，只是需要你用正确的姿势把它「调」出来。于是有了 **Zero-shot Prompting**（直接下指令、不给例子）和 **Few-shot Prompting**（在提示词里塞几个「输入→输出」的例子，也叫 **In-context Learning，上下文学习**）。

本讲重点讲**身份二**，因为这才是你天天调 API、写 Prompt 时真正会碰到的东西。但身份一的历史必须铺垫，因为它决定了「为什么 LLM 能这么玩」。

### 2. 历史脉络：从「教不会」到「不用教」

**（1）前 LLM 时代：Few-shot 是个难题**

2015 年之前，深度学习是「数据饥饿」的典型代表。你给一个图像分类模型 100 万张猫狗照片，它能分得比人还准；但要是只给它 5 张，它几乎必崩。于是「怎么用很少的数据学」成了一个专门的研究方向：

- **2015 年，Brenden Lake、Ruslan Salakhutdinov、Joshua Tenenbaum** 在《Science》上发了经典论文《Human-level concept learning through probabilistic program induction》，直接点破「人看一张图就会认新字母，机器要几百张」这个鸿沟。这是 Few-shot Learning 被推上风口的关键论文之一。
- **2016 年，Oriol Vinyals 等人**提出 **Matching Networks**，第一次把「学习如何对比样本」这件事做成了端到端可训练的框架，是少样本学习的重要里程碑。
- **2017 年，Snell 等人**提出 **Prototypical Networks**（原型网络），思路是「每个类别的样本在向量空间里聚成一个中心点（prototype），新样本看离哪个中心近就归哪类」。直觉极强，是少样本分类的经典方法。
- **2017 年，Chelsea Finn 等人**提出 **MAML（Model-Agnostic Meta-Learning）**，走「元学习（Meta-learning）」路线：不是直接学任务，而是学「一套能快速适应任何新任务的初始参数」，换新任务时微调几步就好。这是「学会学习（Learning to Learn）」的代表作。

这阶段有个共同底色：大家都在想办法**改造模型或训练流程**，让模型天生「省数据」。

**（2）LLM 时代：范式翻转，Few-shot 变成「写例子」**

转折点是 GPT 系列。关键论文是 **2020 年 OpenAI 的《Language Models are Few-Shot Learners》（GPT-3 论文）**。这篇论文做了一件震动业界的事：

> 它证明了一个 1750 亿参数的模型，**完全不用微调（不更新任何权重）**，只要在提示词里给它几个示例（Few-shot），就能在翻译、问答、数学、代码等几十个任务上达到甚至超过当时专门微调的小模型。

作者把这个现象命名为 **In-context Learning（上下文学习）**——模型不是「学会了」，而是「看懂了你给的例子，临时照着做」。这是「少样本」从「训练范式」变成「提示技巧」的分水岭。

**（3）Zero-shot 的独立地位**

其实「不给例子」也能干，GPT-3 论文里也测了 Zero-shot 场景。后来 **2022 年 OpenAI 的 InstructGPT / RLHF 路线**，以及 **Anthropic 的 Claude**，把「听懂指令」这件事做到极致——模型被对齐成「你说人话它照办」，于是大量任务连例子都不用了，Zero-shot 成了默认姿势。今天你用 ChatGPT，绝大多数时候就是 Zero-shot：直接问，不给例子。

### 3. 工作机制：Few-shot 为什么真的管用

这是最该讲透的地方。Few-shot 不更新模型权重，那它到底怎么「起作用」？目前学界的共识是几股力量叠加：

**（1）格式示范（Format / Template Induction）**

模型真正缺的往往不是「知识」，而是「你想要它用什么格式输出」。你给它 2～3 个「问题→答案」的例子，它瞬间就锁定了：哦，你要的是这种格式、这个口吻、这个详细度。这比在指令里啰嗦地描述「请用 JSON 输出、字段叫 xxx」更有效，因为例子是**具象的**，描述是**抽象的**。

**（2）任务唤醒（Task Specification）**

「把这句话翻译成英文」——这个指令本身已经比较清楚了，但对一些模糊任务（比如「给这段文字做情感倾向标注」），光说任务名模型可能拿不准。给几个例子，等于把「你到底要什么」钉死。

**（3）分布对齐（Distribution Matching）**

有研究（比如 **Min et al. 2022《Rethinking the Role of Demonstrations》**）做过一个有意思的实验：把示例里的**标签故意写错**（比如情感任务是「正面」却标成「负面」），模型居然还是表现不错。这说明 Few-shot 的很大一部分收益，来自「示例提供了正确的格式和任务范围」，而不是「模型真的在从示例里学知识」。当然这不是全部——在更复杂任务里，示例的**内容质量**明显影响结果，尤其示例要**覆盖不同情况、错误示例要少、顺序要讲究**。

**（4）注意力机制的直接利用**

从机制层面看，In-context Learning 被理解为：Transformer 的注意力层在「读提示词里的示例」时，就是在做一种**临时、隐式的梯度下降**。2022 年有论文（如 **von Oswald et al. / Dai et al.** 的工作）证明，Transformer 的前向传播在数学上等价于「对某个隐式模型做几步梯度更新」。换句话说，**看例子 = 临时微调了一小下，只不过没写回权重**。这个「上下文即学习」的假说至今仍是活跃研究方向，没完全定论，但方向很清晰。

### 4. 关键概念：Shot 的计数、One-shot 与常见玩法

- **Shot** 就是「示例个数」。0 个示例 = Zero-shot；1 个示例 = **One-shot**；几个到几十个 = Few-shot。
- **One-shot** 是最常用也最容易踩坑的：一个例子既给格式又给内容，模型容易「过拟合」到这一个例子上（比如例子里的数字是 5，模型回答时也总往 5 上靠）。所以实用上，**2～5 个多样化的例子通常比 1 个更稳**。
- **Few-shot 的扩展玩法**：把示例精心挑选、排序，甚至用检索从知识库里自动挑「和当前问题最像」的历史例子塞进去（叫 **Dynamic Few-shot / Retrieval-augmented In-context Learning**），是工程上的进阶操作。
- **Few-shot 和微调（Fine-tuning）的区别**：Few-shot 不改变模型本身，改的是**输入**；Fine-tuning 改的是**模型权重**。前者便宜、灵活、随用随扔；后者贵、持久、但需要数据和算力。下一讲「思维链」你会看到它俩的分工更清楚。

### 5. 前沿进展

- **Few-shot 的「退化」担忧**：随着模型越来越强（尤其推理型模型），很多任务 Zero-shot 已经够好，Few-shot 的边际收益在缩小，甚至有些场景里乱塞例子反而**干扰**模型（因为模型自己的判断比你的烂例子更强）。所以现在的主流建议是：**先用 Zero-shot 试，不行再加例子**，而不是默认上 Few-shot。
- **自动生成示例**：有人让模型自己给自己造示例（Self-generated demonstrations），或用一个弱模型先产出候选示例、再筛选，减少人工写例子的成本。
- **上下文压缩**：示例多了占 Context Window（上下文窗口），于是有了「把几十个示例压缩成几个『精华示例』」的研究，试图在有限的上下文里塞进更多信息量。
- **与思维链合流**：Few-shot 的示例里如果带上「思考过程」而不是只给答案，就是下一讲要讲的 **Chain-of-Thought（思维链）**——这是目前提升推理能力最有效、最便宜的技巧之一。这里埋个钩子。

## 实际场景

- 你第一次给一个新任务写 Prompt，默认就是 **Zero-shot**：直接下指令，不给例子。
- 发现模型输出格式不对、或总理解偏任务，就**补 2～3 个示例**变成 Few-shot，通常立竿见影。
- 做「情感分类、信息抽取、命名实体识别」这类**格式要求严格**的任务，Few-shot 是标准做法：几个「原文→标注结果」的例子一放，模型照猫画虎，准确率大幅提升。
- 调 API 时，你写的 `messages` 里那段「system + 用户指令」是 Zero-shot；一旦在用户消息里塞进「示例输入→示例输出」，你就已经在做 Few-shot 了。
- 面试或看论文时，「Few-shot Learning」和「Few-shot Prompting」是两个考点，前者偏学术范式，后者偏工程技巧，别答混。

## 关联术语

- **Prompt（提示词）**：Few-shot 本质就是在 Prompt 里塞例子，理解它先得理解 Prompt 是什么。
- **Chain of Thought / CoT（思维链）**：Few-shot 的「高阶版」——示例里带上推理步骤，下一讲的主题。
- **Fine-tuning（微调）**：和 Few-shot 相对的另一条「让模型更会干这活」的路线，一个改输入、一个改权重。
- **Context Window（上下文窗口）**：示例要占上下文空间，窗口大小直接限制了你能塞几个例子。
