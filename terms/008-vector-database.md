# 008 · Vector Database（向量数据库）

- ② 中文翻译：向量数据库
- ③ 一句话定义：专门用来存储、索引和快速检索「向量」这类高维浮点数组的数据库，是 RAG、语义搜索、推荐、多模态检索这些 AI 应用的地基之一。
- ④ 核心知识
- ⑤ 实际场景
- ⑥ 关联术语

---

## ③ 一句话定义（展开）

上一讲我们讲了 Embedding（嵌入）：一句话、一张图、一段音频，经过模型编码后会变成一串浮点数，比如 768 维或 1536 维的一个向量。这个向量不是给人看的，它的价值在于——语义相近的东西，向量在空间里也挨得近。

那么问题来了：我有几百万条文档、几千万个商品、上亿个用户画像，每条都对应一个高维向量，用户来一句查询，我要在毫秒级里找出「最相似」的那几十个。传统的关系型数据库（MySQL、PostgreSQL）擅长「精确等于」和「范围查询」，但你要它做「找出和这个向量夹角最小的前 100 个」，它会直接抓瞎——逐条算一遍余弦相似度，数据一大就慢到没法用。

**向量数据库就是为解决这个「高维空间里的最近邻检索（Nearest Neighbor Search）」而生的专用数据库。** 它把「存向量」和「搜相似」两件事都优化到了极致。

## ④ 核心知识

### 1. 先说清楚：向量数据库到底「新」在哪，别被名字唬住

很多人第一次听到「向量数据库」以为是什么全新的黑科技，其实它的本质是一个老问题 + 一套新工程组合：

- **老问题**：近似最近邻搜索（Approximate Nearest Neighbor，简称 ANN）。这个领域在信息检索、计算机视觉里研究了二三十年。
- **新组合**：把 ANN 索引 + 向量存储 + 元数据过滤 + 分布式扩展，打包成一个易用的、专门面向 AI 场景的独立数据库产品。

所以你不必把它想得太玄。它就是个「擅长找相似」的数据库。区别传统数据库的地方就一句话：**传统库回答「有没有 / 等于什么」，向量库回答「像不像 / 最像谁」。**

### 2. 相似度：两个向量怎么算「像」

向量之间的相似度有好几种度量方式，最常用的三个：

1. **余弦相似度（Cosine Similarity）**：看两个向量的「方向」是不是一致，取值 -1 到 1，越接近 1 越相似。它不在乎向量长度，只在乎夹角。这是文本 Embedding 最常用的，因为文本向量的「长度」往往和词频、句子长短相关，我们不希望长度干扰判断。
2. **欧氏距离（Euclidean Distance / L2）**：就是空间中两点的直线距离，越小越像。图像、人脸识别这类场景常用。
3. **内积 / 点积（Inner Product / Dot Product）**：两个向量对应位相乘再相加，越大越像。有些模型（尤其是做过归一化训练的）直接拿它当相似度，计算最省。

选哪种度量，通常取决于你的 Embedding 模型是怎么训练出来的——模型训练时用了哪种目标，你就该用哪种度量去「配套检索」，否则效果会打折。这是新手最容易忽略的坑。

### 3. 核心难题：高维空间的「维度诅咒」

为什么不能暴力逐个算？这里有个反直觉的点，叫 **维度诅咒（Curse of Dimensionality）**：

- 在低维空间（2D、3D），你还能用 kd-tree 之类的树结构高效切分空间、剪枝查找。
- 一旦维度升到几百上千维，空间变得极其「稀疏」，几乎所有点两两之间距离都差不多，树结构的剪枝几乎失效，暴力搜索和「聪明」方法差距急剧缩小。

于是工程界达成共识：**放弃「精确」结果，追求「近似但足够好、且极快」的答案**——这就是 ANN。向量数据库的本质，是「用可控的一点点精度损失，换数量级的性能提升」。典型做法是召回时多搜几个候选（比如你要 top10，我先粗筛 top100），再重排精算，误差通常在个位数百分比以内，但速度能快成千上万倍。

### 4. 索引算法：HNSW、IVF、PQ 三巨头

向量数据库的心脏是「索引」。主流的 ANN 索引算法大致分三类，现代向量库通常把它们组合使用：

**（1）HNSW（Hierarchical Navigable Small World，分层可导航小世界图）**
- 思想：把向量组织成一张多层「图」，每层是一个「小世界网络」（社交网络那种「六度分隔」结构）。
- 查询时从最顶层的稀疏层开始，层层往下「跳」，像导航一样快速逼近目标区域。
- 特点：查询极快、召回率（准确度）高，是当前最主流的默认索引；缺点是构建慢、**内存占用大**（要存整张图）。
- 代表实现：Faiss（Facebook/Meta 开源）、hnswlib。

**（2）IVF（Inverted File Index，倒排索引 + 聚类）**
- 思想：先用 k-means 把所有向量聚成 N 个簇（桶），每个桶一个中心点。查询时先算「和哪个桶中心最近」，只在这个桶（或附近几个桶）里暴力搜。
- 特点：内存省、构建快，适合海量数据；缺点是查询精度受聚类质量影响，需要调「探测的桶数」（nprobe）。
- 常和 PQ 搭配。

**（3）PQ（Product Quantization，乘积量化）**
- 思想：把高维向量切成若干段，每段用「查码本」的方式压缩成一个短编码，用极少的字节近似表示原向量。
- 特点：**极度省内存**，能把向量压缩到原来的 1/8、1/16，代价是精度进一步下降。
- 用法：常作为 IVF 的「压缩存储」层，即 IVF+PQ 组合（Faiss 里的 IVF-PQ 就是经典款）。

一句话记法：**HNSW 快而贵（占内存），IVF 省而稳（要聚类），PQ 省内存但丢精度，工程上常混搭。**

### 5. 光会「搜相似」还不够：过滤（Filtering）是真正的工程难点

真实生产里，几乎不会只做「纯相似搜索」。比如你搜「烟斗保养」，但只想要「价格在 500 元以下、有现货、品牌是 X」的商品。这时要**同时满足：向量相似 + 结构化条件过滤（元数据过滤）**。

这恰恰是向量数据库的深水区，两种朴素做法都有坑：

- **先过滤再搜索（pre-filtering）**：先按结构化条件筛出子集，再在子集里做向量搜索。问题：如果条件筛掉了本来很相似的结果，或子集太小，召回质量差。
- **先搜索再过滤（post-filtering）**：先搜出 top N 相似，再套条件过滤。问题：过滤后可能剩不下几个结果，甚至为空。

所以成熟的向量库（如 Milvus、Weaviate、Qdrant、Pinecone）会做**混合方案**：把标量过滤「下推」进索引内部，在遍历图/桶的过程中边查边过滤，并支持**「过滤 + 相似」联合打分**，尽量兼顾。这也是为什么「向量数据库」不只是「向量检索库」——**元数据过滤能力，是它区别于一个单纯 ANN 库的关键**。

### 6. 历史脉络与人物

- **早在上世纪 70 年代**，高维检索就是数据库和信息检索领域的经典问题（kd-tree 1975 年由 Bentley 提出）。
- **2011 年前后**，深度学习开始在图像领域爆发（ImageNet），「用向量表示语义」这件事开始有实用价值。
- **2013 年**，Mikolov 等人发表 word2vec，首次大规模展示「向量语义」的神奇（king - man + woman ≈ queen）。这让「语义向量」从学术玩具变成工程现实。
- **2017 年**，Meta（当时 Facebook）开源 **Faiss**——这是 ANN 检索的里程碑，把 HNSW、IVF、PQ 等算法做成了工业级、GPU 加速的库，直到今天仍是底层事实标准之一。
- **2018–2019 年**，Milvus（2019 开源）、Weaviate、Pinecone、Qdrant、Vespa 等一批「真正的向量数据库产品」陆续出现，把 ANN 从「库」升级成「带存储、过滤、分布式、一致性保障的完整数据库」。
- **2022 年底 ChatGPT 引爆 RAG**，向量数据库从「小众基础设施」一夜变成 AI 应用的标配组件，进入大众视野。

### 7. 前沿进展与趋势

- **混合检索（Hybrid Search）**：把「向量相似」和「关键词全文检索（BM25）」结合，取长补短——向量擅长语义、BM25 擅长精确术语和人名/编号。很多场景下混合检索的效果明显好于纯向量。
- **重新排序（Rerank）**：粗召回（向量库）→ 精排序（cross-encoder 重排模型），用两层漏斗提质量。
- **向量 + 传统数据库融合**：PostgreSQL 的 pgvector、Elasticsearch、Redis、ClickHouse 纷纷内置向量能力，出现「一个库全搞定」的趋势，向专用向量库发起竞争。
- **多模态向量**：文本、图像、音频统一嵌入同一个向量空间（如 CLIP），实现「文搜图、图搜图」。
- **Binary / 量化向量、GPU 加速、分布式万亿级检索**：朝更大规模、更低成本、更低延迟演进。
- **新一代探索**：出现「学习型索引」「矩阵乘积量化变体」「图+量化混合」等，还有人在研究用「可学习哈希」进一步压缩。

## ⑤ 实际场景（万 sir 会在哪儿碰到它）

1. **RAG 问答**：把你的文档切块、Embedding、存进向量库，用户提问时先从库里召回最相关的几段，再喂给 LLM 生成答案。这是向量数据库最典型的应用，也是「斗物」这类项目如果要做「内部知识问答」时的标准套路。
2. **语义搜索 / 相似商品推荐**：电商里「找相似款」，你上传一张烟斗图，系统返回相近的商品——背后就是图像向量在库里做最近邻搜索。
3. **以图搜图 / 多模态检索**：图片反查、版权查重。
4. **推荐系统**：用户和商品的向量做相似匹配，做「猜你喜欢」。
5. **去重 / 聚类 / 异常检测**：新闻去重、垃圾内容识别、日志异常，本质都是「找相似」。
6. **长时记忆（Agent Memory）**：做 Agent 时，把历史交互 Embedding 存进向量库，后续按语义相关性调取记忆——这是当前 Agent 记忆的主流实现。

## ⑥ 关联术语

- **Embedding（嵌入 / 向量化）**：向量数据库存的「货」就是 Embedding 生成的向量，两者是上下游关系——没有好 Embedding，向量库再快也没用。
- **RAG（检索增强生成）**：向量数据库是 RAG 管线里「检索」这一环的标准落地方式，可以回看第 6 讲。
- **ANN（近似最近邻）**：向量库底层检索算法的统称，理解它你就理解了向量库为什么能「快」。
