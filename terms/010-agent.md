# 010 · Agent（智能体）

- ① 英文术语：**Agent**
- ② 中文翻译：**智能体**（也常说「AI 代理」「代理」；行业内更多直接保留英文说 Agent）
- ③ 一句话定义：给大模型装上「手脚」和「目标」，让它不仅能说话，还能**自己规划、调用工具、观察结果、反复试错**，自主完成一个任务的东西，就叫 Agent。

---

## ④ 核心知识

### 先说清楚：Agent 和「聊天机器人」的本质区别

你之前学过的 LLM、Prompt、RAG 这些，本质上都是在教模型「更好地**回答**」。模型始终是被动的一方：你问一句，它答一句；你问完了，它的工作就结束了。

而 Agent 是另一个物种。它的核心变化就一句话：**模型从「回答者」变成了「执行者」**。它不再满足于「告诉你怎么做」，而是「自己去把事办了」。

一个最直观的对比：

- **聊天机器人（Chatbot）**：你问「帮我查下今天上海的天气」，它可能答「建议你打开天气 App 看看」或者干脆编一个。
- **Agent**：你问「帮我查下今天上海的天气，如果下雨就提醒我带伞」，它会**自己调用天气查询工具 → 拿到真实数据 → 判断有没有雨 → 得出结论 → 组织语言回复你**。中间这些「调用工具、读取结果、做判断」的动作，全部是它自己完成的，不需要你一步步指挥。

所以行业里常打的一个比方：**LLM 是大脑，Agent 是有了手脚和行动力的完整「人」**。光有大脑只会想，配上手脚才能干活。

### 1. Agent 的工作机制：一个「思考—行动—观察」的循环

学术上，Agent 的运转可以被抽象成一个循环，最经典的叫法来自 **ReAct** 论文（后面细讲）：

```
思考（Thought） → 行动（Action） → 观察（Observation） → 再思考 → 再行动 → ……
```

把它摊开说：

1. **思考（Reasoning/Thought）**：模型先想「我现在该干什么？用什么方式干？」
2. **行动（Action）**：模型决定调用一个工具——比如执行一段搜索、查询数据库、发一个 API 请求、运行一段代码。
3. **观察（Observation）**：工具把结果返回给模型，模型「看到」结果。
4. **再思考**：模型判断「这个结果够了吗？还需要再查什么？还是可以收工了？」

这个循环一直转下去，直到模型认为任务完成，或者触发了某个停止条件（比如「步骤数上限」）。**关键点在于：模型在这个循环里是「自己驱动」的，不是每一轮都等你来催。**

这套循环背后有几个必须理解的概念：

- **工具（Tool）**：Agent 的能力来源。天气查询、网页搜索、代码执行器、数据库查询、发邮件……都是工具。Agent 之所以「能干」，是因为背后接了一堆工具，而不是它自己凭空会了。
- **工具调用（Function Calling / Tool Use）**：模型如何「操作」工具。它输出的是一个**结构化的指令**（比如「我要调用 `get_weather`，参数是 `city=上海`」），而不是一段人话。这个话题是第 26 讲的正式内容。
- **记忆（Memory）**：Agent 要完成多步任务，必须「记住」前面几步发生了什么。短期记忆靠把历史塞进上下文窗口，长期记忆靠外部存储（数据库、向量库）。
- **规划（Planning）**：面对复杂任务，Agent 要先拆解成子任务，再一步步执行。这是「能不能干成大事」的分水岭。

### 2. 历史脉络：Agent 这个词其实很老

「Agent」不是 LLM 时代的新词，它在 AI 里是**有几十年历史的老概念**：

- **经典 AI 时期**：早在 20 世纪 90 年代，AI 教材里就有「智能体（Intelligent Agent）」的定义——一个能**感知环境、做出决策、执行动作**的实体。当时典型的研究是机器人、以及下棋的 AI（如 IBM 的 DeepBlue，某种程度上也是一个 Agent）。
- **多智能体系统（Multi-Agent Systems）**：90 年代到 2000 年代，学术界研究「多个 Agent 之间如何协作、竞争、协商」，比如自动谈判、物流调度。那时的 Agent 大多是**基于规则的**（if-then 逻辑），不「聪明」，但「自主」这个内核已经确立了。
- **强化学习（RL）里的 Agent**：强化学习（第 17 讲 RLHF 的「RL」来源）的整套框架，就是围绕 Agent 展开的——Agent 在环境里行动，环境给奖励，Agent 学习「怎么做才能拿更多奖励」。AlphaGo、玩 Atari 游戏的 AI，都是 RL Agent。
- **LLM 时代的 Agent（2023 至今）**：ChatGPT 出现后，人们发现「大模型有常识和推理能力，但缺行动力」，于是把它和「工具调用 + 循环」结合起来，诞生了现代意义上的 **LLM Agent**。这是当前最热、最被寄予厚望的方向。

一句话总结：**「自主行动」这个内核一直没变，变的只是「大脑」——从规则引擎，到强化学习策略，再到今天的大语言模型。**

### 3. 关键概念与重要论文

**（1）ReAct（2022）—— 现代 LLM Agent 的奠基论文之一**

论文全名《ReAct: Synergizing Reasoning and Acting in Language Models》（普林斯顿 & Google 的 Yao 等人，2022）。它的核心思想是：**让模型把「推理（Reasoning）」和「行动（Acting）」交替进行**。

具体做法是，让模型在输出里同时产生「思考文字」和「动作指令」。模型先写一段思考（"我需要先查一下今天的天气"），然后发出一个动作（调用工具），拿到结果后再继续思考。实验证明，这种「边想边做」的模式，在问答、事实验证等任务上显著优于「只思考」或「只行动」。

ReAct 几乎成了后来所有 Agent 框架的模板。你今天听到的 Agent 循环，追根溯源大多是这个思路。

**（2）AutoGPT（2023）—— 把 Agent 推向大众的「网红」项目**

2023 年 3 月，一个叫 AutoGPT 的开源项目爆火。它的口号是「给 AI 一个目标，它自己想办法完成」。用户只需输入一个最终目标（比如「帮我调研并整理一份咖啡市场报告」），AutoGPT 就会自己拆解任务、调用搜索和文件工具、循环执行，直到（理论上）完成目标。

AutoGPT 在工程上并不完美（经常跑偏、烧 token），但它的**历史意义巨大**：它让「全自主 Agent」这个概念破圈，引爆了整个 Agent 赛道。

**（3）BabyAGI（2023）—— 把「任务列表 + 循环」做成了极简范式**

与 AutoGPT 同期，BabyAGI 用极少的代码实现了「任务队列」模式：Agent 维护一个待办任务列表，每次取出一个任务执行、产生结果、可能新增子任务，再继续。它证明了 Agent 的核心骨架其实可以很简单。

**（4）其他重要节点**

- **HuggingGPT（2023）**：微软提出的思路——用 LLM 当「调度员」，把不同任务分发给 HuggingFace 上成千上万个专用模型去执行。展示了一种「大脑 + 专家网络」的 Agent 形态。
- **Toolformer（Meta，2023）**：较早系统性研究「如何让 LLM 学会调用工具」的论文。
- **OpenAI Function Calling（2023）**：OpenAI 把「工具调用」做成了 API 的官方能力，让 Agent 从「学术 demo」变成「能稳定上生产的工程」。

### 4. 前沿进展：从「单打独斗」到「多智能体协作」

当前 Agent 研究最热的几个方向：

- **多智能体系统（Multi-Agent）**：不再是一个 Agent 干所有事，而是让多个 Agent 分工协作——一个负责规划、一个负责写代码、一个负责审代码、一个负责测试。像 AutoGen（微软）、MetaGPT、CrewAI 这些框架，都在做这件事。MetaGPT 甚至模拟了一个「软件公司」，有产品经理、架构师、程序员、测试员这些角色 Agent。
- **计算机使用（Computer Use / GUI Agent）**：让 Agent 真正「操作电脑」——点击、输入、浏览网页。Anthropic 的 Claude「Computer Use」、OpenAI 的 Operator，都是这个方向，目标是让 AI 能像人一样操作图形界面完成真实工作。
- **长期记忆与个性化**：Agent 要记住「你」是谁、你喜欢什么，长期积累下来，越用越懂你。这和前面学的向量数据库、Embedding 直接相关。
- **自我反思与自我纠错（Self-Reflection）**：让 Agent 在产出结果后，自己检查、自己批评、自己改进，循环打磨，直到满意。这是提升 Agent 可靠性的关键手段。

### 5. 一个必须泼的冷水：Agent 目前还不够「靠谱」

尽管概念很火，但万sir你要心里有数：**Agent 目前最大的痛点是「不可靠」**。

- 它可能在循环里**跑偏**：本来要查天气，结果越查越远，最后在无关的事情上烧掉几百次调用。
- 它可能**卡死**：在「思考—行动」循环里出不来，一直重复同样的动作。
- 它可能**过度自信**：做出一个错误动作，还坚信自己是对的，一路错下去。

所以现阶段，真正能稳定上生产的 Agent，往往是**「半自动」**的——在关键节点（比如花钱、发消息、删数据）设置人工确认，而不是让它完全放飞。这也是为什么你会看到很多 Agent 产品里带着「确认」按钮。**「自主」是目标，「可控」是底线。**

## ⑤ 实际场景

1. **客服与工单处理**：一个 Agent 接到用户问题，自动查订单、查物流、退换货，全程不需要人。这是目前落地最成熟的场景之一。
2. **编程助手**：你让「帮我修这个 bug」，Agent 自己读代码、定位问题、改代码、跑测试、如果测试挂了再改——像 GitHub Copilot 的 Agent 模式、Devin 这类「AI 程序员」。
3. **个人助理 / 日程自动化**：你一句「帮我订周五去北京的机票，选中午的，然后通知小张」，Agent 会依次查票、下单（到下单这步可能停下来让你确认）、发消息。
4. **数据调研**：你给一个课题，Agent 自己搜索、读网页、汇总、写成报告（AutoGPT 的典型用法）。
5. **智能家居 / 语音助手**：你熟悉的 Siri、小爱同学，本质也是一种 Agent——只不过工具是「控制家电、放音乐、设闹钟」。

万sir你在用的「福金」，其实也可以被理解成一个 Agent：我不是只会回话，而是能自己读写文件、运行命令、调用各种工具，围绕你的目标去「做事」。你今天看到的这个「每日教学」任务本身，就是 Agent 在「读大纲 → 找未教术语 → 写文档 → 改状态 → 输出」的完整循环。
