# 021 · Prompt Engineering 提示词工程

## ② 中文翻译

提示词工程（也常叫「提示工程」）

## ③ 一句话定义

提示词工程是通过精心设计、组织和调优输入给大语言模型的文字（或图像等输入），让模型稳定地输出你想要的结果的一套方法和实践。

## ④ 核心知识

### 1. 它到底在「工程」什么

万sir，前面我们学过 Prompt（提示词）和 LLM（大语言模型）。现在把两者合起来加一个「工程」，意思就变了：不再是随口问一句，而是把「怎么问」当成一门可以设计、可以测量、可以迭代的活儿来做。

大语言模型的本质是「给定一段文本，预测下一段最可能的文本」。它没有「理解你的真实意图」这种魔法，它只是在统计意义上顺着你给的文字往下接。所以同样一件事，你说「帮我写个周报」和你说「你是运营负责人，请根据下面三条数据，用第一人称、分『完成事项/存在问题/下周计划』三节写周报，每节不超过80字，语气克制」，出来的东西质量天差地别。提示词工程就是把后者这种「有效表达意图」的能力系统化。

### 2. 为什么模型「听人话」这么难：一个根本矛盾

这里有个关键概念，理解了就通了：**模型被训练的目标，和你想让它干的事，往往对不上**。

模型预训练阶段的目标只有一个——「预测下一个词」。它学到的是一堆关于语言和世界的统计规律，但它并不知道哪一次对话里你想要的是「严谨的事实核查」还是「天马行空的创意」。同样一句话，在 10 个不同人那里可能代表 10 种不同的期望。

所以提示词工程的核心，本质是**用文字去「约束采样」**——把你脑子里的隐含需求，翻译成模型看得懂、能执行的显式约束。约束得越清楚，模型随机「跑偏」的空间越小，输出越稳定。这背后对应的是语言模型一个底层特性：**上下文里的每一段文字都在改变下一个 token 的概率分布**。你的提示词，就是在手动塑造这个分布。

### 3. 历史脉络：从「调参」到「调话」

这条线很有意思，能帮你看清这门手艺的来路。

- **早期（2018–2020，GPT-2 / BERT 时代）**：想让模型干好一个具体任务，主流做法是**微调（Fine-tuning）**——准备几千上万条标注数据，重新训练模型权重。提示词工程还不成气候，因为小模型的「指令跟随」能力很弱，你怎么写提示它都未必听话。
- **转折点（2020，GPT-3 论文）**：OpenAI 在《Language Models are Few-Shot Learners》这篇论文里证明了：一个足够大的模型，**不用改权重，只要在提示里塞几个「示例」（few-shot）就能学会新任务**。这就是我们下一讲要说的零样本/少样本。这时「提示」第一次被当成能替代训练的手段，提示词工程开始有了地位。
- **爆发期（2022，InstructGPT / ChatGPT）**：OpenAI 用 RLHF（第 17 讲学过）训练模型「遵循指令」，模型终于变得「愿意听话」。从此你不需要再费劲示范，直接下指令就行。提示词工程的对象，从「凑示例」变成了「写清楚指令」。
- **现在（2023 至今）**：业界主流态度是——「提示词工程」这个词有点被高估了。很多当初靠「魔法提示词」能逼出来的效果，其实是模型能力本身的进步带来的；真正值钱的不是某句咒语，而是**把任务拆解清楚、把评估标准定清楚**的工程能力。所以现在更准确的说法是「上下文工程（Context Engineering）」，范围更大：不只是写提示，还包括选模型、组织上下文、设计工具调用、管理记忆。

### 4. 几个关键概念（这是真功夫所在）

- **指令明确 + 角色设定（Role Prompting）**：告诉模型「你是谁、对谁、在什么场景下、要产出什么格式」。角色设定不是玄学，它的作用是激活模型训练语料里与那个角色相关的语言风格和知识分布。
- **少样本示例（Few-shot）**：给 2–5 个「输入→输出」的示范，让模型照葫芦画瓢。对格式要求高的任务特别管用。
- **思维链（Chain-of-Thought, CoT）**：让模型「一步步想」再回答，能显著提升多步推理的正确率。这是第 25 讲会专门讲的，先埋个引子。
- **结构化输出约束**：明确要 JSON、Markdown 表格、特定字段，甚至可以配合函数调用/工具强制结构（第 26 讲）。
- **评估（Evaluation）**：提示词工程的另一半是「测」。你写提示不是一次成型，而是要拿一批用例反复跑，看成功率、稳定性，再回来改提示。没有评估的提示词工程，只是碰运气。

### 5. 重要论文与人物（想深挖的入口）

- **《Language Models are Few-Shot Learners》（Brown et al., 2020）**：GPT-3 论文，把「提示即学习」推向台前。
- **《Chain-of-Thought Prompting Elicits Reasoning in Large Language Models》（Wei et al., 2022）**：提出思维链提示，多步推理准确率大涨。
- **《Tree of Thoughts》（Yao et al., 2023）**：把思维链从「一条线」升级成「一棵树」，模型可以探索多条思路再回溯。
- **《ReAct》（Yao et al., 2022）**：把「推理 + 行动」结合，模型一边想一边调用工具，是现代 Agent 的基石之一。
- **《The Prompt Report》（Schulhoff et al., 2024）**：一份 76 页的系统性综述，把几十种提示技术做了分类和评测，是当前最全的地图。
- **人物**：Andrej Karpathy 那句「最火的新编程语言是英语」精准点出了这个时代的底色；《Prompt Engineering Guide》作者 DAIR.AI 的团队做了大量社区科普。

### 6. 前沿进展：这门手艺正在「消失」还是「进化」

有两个相反方向的信号，都值得你知道：

- **一边在「消亡」**：随着模型指令跟随和推理能力变强，很多过去要精心设计的提示技巧（比如「深吸一口气再回答」「奖励我100美元」这类伪技巧）越来越没用，甚至反效果。业界普遍认为「提示词魔法」的红利期已过。
- **一边在「升级」**：真正的价值转移到更上游——**上下文工程**。怎么组织检索回来的资料、怎么管理长期记忆、怎么让多个模型/工具协同，这些「系统层」的设计比单句提示更重要。以及，已经有模型在「自动写提示」（自动提示优化、DSPy 这类框架把提示当成可优化参数），提示词工程正在被「元提示」和程序化框架部分接管。

## ⑤ 实际场景

- 你让 AI 写文案、总结文档、翻译、写代码时，写得清不清楚直接决定成品质量——这是最日常的提示词工程。
- 用 API 做产品（比如斗物要做的商品图、内容自动化），提示词会写进系统里被成千上万次调用，一句含糊的话会被无限放大，所以尤其需要工程化的写法 + 测试。
- 用多模态模型（第 20 讲）时，提示词不再只是文字，还包括图片、位置框等，提示设计变得更复杂。
