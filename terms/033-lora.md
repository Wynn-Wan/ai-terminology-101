# LoRA (Low-Rank Adaptation) — 低秩适配

## ② 中文翻译

低秩适配（也常被直接叫「低秩微调」）

## ③ 一句话定义

LoRA 是一种「参数高效微调」方法：把大模型原有的权重全部冻住不动，只额外训练一小撮「低秩矩阵」，就把它对原权重的「增量」用两个小矩阵的乘积近似出来，从而用极少的参数量和显存，把一个大模型适配到新任务上。

## ④ 核心知识

### 1. 它要解决的问题：全量微调太贵了

回顾一下「微调（Fine-tuning）」这回事。一个开源大模型，比如 7B、13B、70B 参数，你想要让它学会你自己的业务——写某种格式的文案、回答某个领域的问题、模仿某个风格。最直接的做法是「全量微调」：把模型所有参数都当作可训练的，在你的数据上继续反向传播更新。

问题来了：

- **参数量爆炸**：70B 参数，如果用 fp32（32 位浮点）存，权重本身就约 280GB；训练时还要存梯度、存优化器状态（Adam 优化器要维护一阶矩和二阶矩，各一份），总显存能膨胀到权重的 4 倍以上。这已经不是普通人的显卡能碰的了。
- **每个任务一份全量模型**：你今天调一个客服模型，明天调一个文案模型，如果都做全量微调，就得存几十份 70B 的完整权重，存储和部署成本直接上天。

所以学界和工业界一直在找一条路：**能不能只训练很少的参数，就让大模型学会新任务？** 这条路线统称「参数高效微调」（Parameter-Efficient Fine-Tuning，简称 PEFT）。

### 2. 历史脉络：PEFT 的演进，以及 LoRA 站在谁的肩膀上

LoRA 不是凭空冒出来的，它前面有一串前辈：

- **部分层微调 / 只微调分类头**：最早、最糙的做法。冻住主体，只训最后一层或几层。便宜，但表达能力弱，能学的范围有限。
- **Adapter（适配器）**：2019 年 Houlsby 等人提出，在 Transformer 的每一层里**插入**一个小型神经网络模块，只训练这些小模块。缺点是：插在中间会**增加推理时的计算量**，因为推理时这些 Adapter 也要跑，带来额外延迟；而且训练时这些层还得做反向传播，显存省得不够彻底。
- **Prefix-tuning / Prompt-tuning**：2021 年，Li & Liang 提出 Prefix-tuning，Learned Prompt 之类的思路，把「可训练的软提示」挂在输入前面，只训练这一小段虚拟 token。思路轻量，但能塞进去的「知识容量」有限，而且对模型原本的 token 长度有挤压。

到 2021 年，微软的 Edward Hu（胡越）等人发表了那篇著名的论文 **《LoRA: Low-Rank Adaptation of Large Language Models》**，提出一个非常优雅的洞察，把上面这些问题基本一锅端了。

### 3. 核心洞察：权重更新是「低秩」的

LoRA 的关键假设（也是它的名字由来）是：**模型在适应下游任务时，权重矩阵发生的「变化量」具有很低的「内在秩」（low intrinsic rank）**。

这是什么意思？先说「秩」（rank）这个词。一个矩阵的秩，可以粗糙地理解成它里面「真正独立的信息维度有多少」。一个 4096×4096 的权重矩阵，表面上有 1600 多万个数字，但如果它的「有效信息维度」其实只有几十，那这些数字之间就有大量冗余——大部分数字都是那几十个「基础方向」线性组合出来的。

LoRA 的作者观察到：全量微调后，权重矩阵的变化量 ΔW（就是「新权重 − 原权重」），虽然尺寸巨大，但它可以被一个**很低秩**的矩阵很好地近似。换句话说，微调真正改变的，其实只是权重空间里很窄的几条「方向」，而不是整个 4096 维空间。

既然 ΔW 是低秩的，那它就可以被分解成两个瘦矩阵的乘积：

```
ΔW = B × A
```

其中，原权重 `W₀ ∈ R^{d×k}`，而 `B ∈ R^{d×r}`、`A ∈ R^{r×k}`，这个 r 就是「秩」，是一个很小的数，比如 8、16、32、64。这样，原本要更新 d×k 个参数，现在只需要训练 r×(d+k) 个参数——对于 4096×4096 的矩阵，取 r=16，参数量就从 1600 万降到约 13 万，**缩小了 100 倍以上**。

### 4. 工作机制：前向和反向到底怎么变

LoRA 改造后的前向计算长这样：

```
h = W₀x + (α/r) · BAx
```

拆开讲：

- **`W₀x`**：原始冻结权重的输出，这部分永远不变。
- **`BAx`**：低秩增量。先用 A（从 k 维压到 r 维）做一个降维，再用 B（从 r 维升回 d 维）做一个升维，就得到对原输出的一个「修正量」。
- **`α/r`**：一个缩放因子，α 是超参数（缩放尺度），除以 r 是为了让缩放和秩解耦——你调大 r 的时候，不一定要同步调大 α，行为更可控。

两个关键设计细节，值得单独拎出来说：

**（1）初始化让模型「起步时零改动」。** A 用随机高斯初始化，B 用全零初始化。这样训练一开始，ΔW = B×A = 0，模型输出和原模型**完全一致**。这很重要：它保证 LoRA 的起点就是那个已经很强的大模型，而不是一个被随机初始化「污染」过的状态。

**（2）只对 LoRA 参数做反向传播。** 因为 W₀ 被冻结，梯度只需要流过 A 和 B 这两条窄路。这意味着：

- **显存大省**：不用为 W₀ 存梯度，也不用为 W₀ 维护 Adam 优化器状态，显存需求从「权重的 4 倍」降到「接近只存权重本身」。
- **训练更快**：要更新的参数少了，计算量自然也小。

### 5. LoRA 为什么这么好用（几个工程上的「白送」优势）

- **可合并、零推理开销**：训练完，你只需要把 `W = W₀ + (α/r)·BA` 直接算出来，把增量「焊」回原权重里。这样推理时模型结构、大小、速度**跟原模型一模一样**，没有任何额外延迟——这是它相比 Adapter 最大的优势。
- **可插拔、多任务复用**：一个基座模型，可以为不同任务各训一个很小的 LoRA（可能只有几 MB 到几百 MB），用哪个任务就加载哪个 LoRA，热插拔。同一个基座 + N 个 LoRA，替代了 N 份全量微调模型。
- **参数即「补丁」**：LoRA 文件小到可以当附件分享，直接催生了后面 Stable Diffusion 社区里铺天盖地的「风格 LoRA」「角色 LoRA」——下载一个几十 MB 的文件，就能让底模学会某个画风或某个角色，这就是 LoRA 的玩法。

### 6. 重要人物与论文

- **Edward Hu（胡越）** 等人，微软，2021，《LoRA: Low-Rank Adaptation of Large Language Models》。这是本方法的开山论文，arXiv 编号 2106.09685，如今引用量早已是数万级别，是 PEFT 领域绕不开的里程碑。
- **QLoRA（2023）**：Tim Dettmers 等人提出，把 LoRA 和「量化」结合——基座权重用量化（尤其是 4-bit 的 NF4 格式）压缩后再挂 LoRA。它让一个 65B 的模型能在**单张 48GB 显卡**上完成微调，把「本地微调大模型」这件事真正普及给了个人和小团队。这是 LoRA 最重要的衍生工作之一。
- 后续变体还有 **AdaLoRA**（自适应分配各层的秩）、**DoRA**（Weight-Decomposed Low-Rank Adaptation，把权重分解为「幅度」和「方向」两部分来学）、**LoRA+**（给 A 和 B 设不同的学习率以加速收敛）、**rsLoRA**（让秩可以调得更大而行为稳定）等，说明这个方向至今仍在被持续改进。

### 7. 前沿进展与边界

LoRA 早已溢出 NLP，跑到视觉、多模态、扩散模型里去了。尤其值得一提的是它在**图像生成（Stable Diffusion）**里的地位：LoRA 成了社区训练「风格/角色/概念定制模型」的事实标准，是普通人也能上手的「炼丹」工具。

它也不是没有局限：

- **容量上限**：低秩假设不是万能的。如果新任务和预训练差异极大（比如要学完全不同的语言、全新的知识领域），低秩增量可能装不下，此时 LoRA 的表现会打折扣，可能需要增大秩 r，或者退回到更重的微调手段。
- **超参敏感**：秩 r、缩放 α、学习率、dropout 这些要调，r 和 α 的关系（通常取 α = r 或 2r）有经验值，但换个模型、换批数据往往要重调。
- **不擅长「注入全新知识」**：LoRA 更适合做「风格迁移」「指令跟随」「格式对齐」这类「行为适配」，对「往模型脑子里灌新事实」的效果，常常不如 RAG（检索增强）来得可靠——这又和之前讲过的 RAG 串起来了。

一句话收尾：**LoRA 用「冻结大权重 + 只训低秩增量」的巧劲，把大模型微调从「服务器集群才玩得起」拉到了「一张消费级显卡就能玩」，是今天开源模型生态繁荣的一块重要基石。**

## ⑤ 实际场景

- **本地微调开源模型**：你在自己电脑上想把 Qwen、Llama 这类开源模型调成「斗物」项目的专属文案或客服助手，直接跑 LoRA（或者 QLoRA），几十 GB 显存需求降到几 GB 到十几 GB，个人显卡就能跑。
- **Stable Diffusion 画风定制**：在 C 站（Civitai）下载各种 LoRA 文件，让底模学会某个画风、某个人物、某类场景，这是你如果做图时几乎一定会碰到的东西。
- **多任务热插拔**：一个基座模型挂多个 LoRA，同一台机器按需切换「翻译 LoRA」「总结 LoRA」「客服 LoRA」，省存储、省部署成本。
- **在已有开源生态工具里看到它**：HuggingFace 的 PEFT 库、LLaMA-Factory、Unsloth 这些微调工具，LoRA 都是默认主角，你实际动手微调时第一套基本就是 LoRA 全家桶。

## ⑥ 关联术语

- **Fine-tuning（微调）**：LoRA 是微调的一种「省参数」实现方式，属于 PEFT 家族。
- **Quantization（量化）**：和 LoRA 结合就是 QLoRA，把基座权重压成 4-bit，进一步降低微调门槛（第 35 讲会专门讲）。
- **Attention（注意力机制）**：LoRA 最常挂载的地方就是 Transformer 里的注意力层的 Q、K、V、O 投影矩阵，第 36 讲深入注意力时会再见面。
