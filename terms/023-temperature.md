# 023 Temperature

- ② 中文翻译：温度（采样参数）
- ① 英文术语：Temperature

## 一句话定义

Temperature 是大语言模型在「生成下一个词」时用来控制随机程度的一个旋钮：数值越低，输出越保守、越可预测；数值越高，输出越大胆、越发散。

---

## 核心知识

### 1. 先搞懂一件事：模型从来不「选」一个词，它给每个词打一个概率分

很多人以为 ChatGPT 是「想好一个词，然后说出来」。其实不是。

每次模型要吐出下一个 token 时，它内部会先算出**整个词表里每一个候选词的概率分布**。假设词表有 5 万个词，那这一步就是给 5 万个词各自打一个分数，比如「我」0.3、「我们」0.2、「你」0.15……这些分数加起来等于 1。

那么问题来了：拿到这堆概率之后，模型该**怎么挑**？

- 最简单粗暴的办法是「谁分高就用谁」，这叫**贪心解码（greedy decoding）**。缺点是它永远走同一条路，生成的内容千篇一律、容易绕圈。
- Temperature 就是另一套「怎么从概率分布里抽词」的规则里，最关键的那个调节参数。

### 2. Temperature 到底在数学上做了什么

在抽词之前，模型会先把每个词的「原始分数」（专业叫 **logits**）除以一个数，这个数就是 Temperature（记作 T）。然后再做 **softmax**，把处理后的分数重新归一化成概率，最后按这个新概率去抽样。

直观看效果：

- **T = 1**：不改变原始分布，模型「本性出演」，按它自己算出来的概率抽词。这是大多数模型的默认值。
- **T < 1（比如 0.2、0.5）**：相当于把分数「放大差距」，本来概率高的词会被推得更高，低的被压得更低。分布变「尖」。结果：模型越来越偏向选最可能的那个词，输出稳定、严谨，但也越来越单调、缺乏创造性。
- **T > 1（比如 1.2、1.5）**：相当于把分数「拉平差距」，本来冷门的词概率被抬高了。分布变「平」。结果：模型开始愿意选一些不太常见的词，输出更跳脱、更有「惊喜感」，但代价是更容易胡说八道、跑题。
- **T → 0**：极限情况，分布尖到极点，每次都几乎必然选最高分的那个词，退化成近似贪心解码。
- **T → ∞**：极限情况，分布被彻底抹平，每个词概率差不多，等于**纯随机瞎抽**，输出会变成乱码。

一句话总结：**Temperature 是在「确定性」和「随机性」之间滑动的滑杆。**

### 3. 别和「抽样方法」混为一谈

Temperature 只是「采样」这套大流程里的一个参数。它经常和另外两个采样技术一起出现，容易搞混，这里帮你区分清楚：

- **Top-p（nucleus sampling，核采样）**：只从「累计概率达到 p 的一小撮词」里抽，把后面那些长尾的低概率词直接砍掉。它控制的是**候选词的范围**。
- **Top-k**：只保留概率最高的前 k 个词，砍掉其余。也是控制**候选词的数量**。
- **Temperature**：在「已经定好的候选集合」里，进一步**调节每个词概率的陡峭程度**，控制的是**分布的锐度**。

实际工程里，这三者经常叠着用：先 Top-p / Top-k 收窄范围，再用 Temperature 调锐度。它们管的是同一件事的不同侧面。

### 4. 历史脉络：这个「温度」从哪来

「Temperature」这个名字来自物理学里的**玻尔兹曼分布（Boltzmann distribution）**，描述粒子在不同能量状态上的分布规律。统计力学里有个关键量叫「温度」，温度越高，粒子越倾向占据高能态、分布越均匀；温度越低，粒子越集中到低能态。

机器学习很早就把这个思想借过来了。上世纪八九十年代，**玻尔兹曼机（Boltzmann Machine）**和**受限玻尔兹曼机（RBM）**里就用「温度」控制采样；**知识蒸馏（Knowledge Distillation）**里也有个著名的「温度 softmax」技巧——Hinton 那篇 2015 年的经典论文《Distilling the Knowledge in a Neural Network》里，就是用提高温度来「软化」教师模型的概率，让学徒模型学到更丰富的软标签。

所以「Temperature」不是一个新词，是神经网络圈子沿用了三四十年的老概念，只是到了 LLM 时代，因为它直接决定「说话稳不稳、有没有创意」，才被普通用户高频看见。

### 5. 关键人物与论文

- **Geoffrey Hinton**：深度学习奠基人之一，2015 年知识蒸馏论文里把「温度」这个技巧推到了主流视野（虽然原理更早就有）。
- **Ackley、Hinton、Sejnowski（1985）**：玻尔兹曼机论文，早期「温度采样」思想的直接源头之一。
- **Ari Holtzman et al.（2019/2020）**：《The Curious Case of Neural Text Degeneration》，这篇是批评「纯贪心/纯随机生成」的经典论文，也正是它把 **Top-p（核采样）**推成主流，间接塑造了今天「Temperature + Top-p 一起调」的标准玩法。

### 6. 前沿进展

- 现在的模型层（比如 OpenAI、Anthropic 的 API）通常**推荐用户不要乱动 Temperature**，或者只给一个窄范围（如 0 到 2 之间，甚至有的接口已弱化这个参数）。原因是现代对齐后的模型内部已经很「懂事」，官方把推荐值调好，用户乱调反而破坏效果。
- 有些新模型/推理框架开始用**动态温度（dynamic temperature）**，在生成过程中根据上下文自动调整随机性，而不是全程固定一个值。
- 在「推理型模型」（擅长数学、代码的 o1 / Claude 思考类模型）里，Temperature 的作用被有意**压制**，因为这些模型要的是稳定可靠的推理链，不是灵光一现的创意。

## 实际场景

- 你在 OpenAI、Anthropic、各家 API 的调用参数里，几乎一定会看到 `temperature` 这个字段。
- 做「客服问答、知识库问答、代码补全」这类要求**准确、稳定**的任务，通常把 Temperature 调低（0～0.3）。
- 做「写文案、写故事、头脑风暴、起标题」这类要**创意和多样性**的任务，可以调高（0.7～1.0，甚至更高）。
- 调试模型「总是答得一样」或「总在胡扯」时，第一时间先怀疑 Temperature 设置，再怀疑别的。

## 关联术语

- **Token（词元）**：Temperature 调节的，正是「下一个 token」的抽样概率，理解它是理解 Temperature 的前提。
- **Top-p / Top-k（核采样 / 前 k 采样）**：和 Temperature 并肩作战的另两个采样参数，下一讲「Zero-shot / Few-shot」之后，你会经常在 API 文档里同时看到它们仨。
- **Inference（推理）**：采样发生在推理阶段，是「模型算答案」的最后一步。
